# ACE v0.18.0 release record

## Developer acceptance (2026-10-02)

The developer accepted the current v0.18 alignment as sufficient for this
milestone: 「0.18版本達到這樣就可以了，留下紀錄然後準備合併進main，然後留下tag」.
The developer subsequently selected source-root normalization before release.
This record supersedes earlier documents' broader scientific release gates
for this milestone; it preserves their unresolved findings as limitations.

The accepted evidence is:

- Manus 208 singleACE saturated +1 K bubble, three hours, with native
  precipitation; the original no-precipitation reference remains preserved.
- Manus 208 multiACE outer ACE 8 MF pulse, twelve hours, native precipitation,
  all eight ACEs evolving; combined eight-row MATLAB/Fortran/difference plots.
- The shared sounding is 1998-08-10 07:00 Manus local time
  (1998-08-09 21:00 UTC), verified against the original source NetCDF.
- Both implementations start from matched states and complete these cases
  with finite saved prognostic fields, nonnegative total water and active
  precipitation. The observed physical evolution is accepted for v0.18.

| Maximum absolute difference | SingleACE, 3 h with precipitation | MultiACE, 12 h |

| theta_e (K) | 7.914900e-8 | 7.406045e-5 |

These values describe the accepted runs; they are not universal numerical
tolerances for later versions. MultiACE ACE 1 peaks near 17.962021
kg m-2 s-1 at 9.3167 h and 7.35 km in both implementations.

## Normalization and local release procedure

Current sources are promoted to `matlab/` and `fortran/`; migration-only
copies leave the current tree with all previous ancestry and provenance
preserved. The [normalization record](../migration/v018_normalization.md)
and [per-file manifest](../migration/v018_normalization_manifest.json)
identify every promotion, retirement and path-only source change.

The normalized production sources were tested at `9665658`. The GNU build
passed, and default versus explicitly selected shared-input initialization
was exactly equal in every saved MATLAB field and the Fortran binary dump:
[default-input evidence](v018_normalization_default_input.json).
All 384 normalization-manifest entries were also checked against the
preserved recovery commit and the current files.

Both three-hour singleACE cases passed their frozen-reference checks and
exactly reproduced every saved numerical value from their pre-normalization
runs, including all eight ACEs and precipitation diagnostics:
[no precipitation](v018_normalization_single_no_precip.json) and
[native precipitation](v018_normalization_single_precip.json).
The verification tool is `tests/alignment/verify_source_normalization.py`.
Exact equality here establishes preservation by a structural change; it
does not impose equality between MATLAB and Fortran or a later model version.

The twelve-hour multiACE rerun also passed. All 721 saved time points,
all eight ACEs, all three prognostic fields, initialization, coordinates
and precipitation diagnostics exactly reproduced the pre-normalization
run within each implementation:
[multiACE normalization evidence](v018_normalization_multi_12h.json).
Both implementations retained finite saved states, nonnegative total water
and active native precipitation. Existing comparison plots remain valid
because their underlying numerical values are unchanged.

Original release disposition (2026-10-02): merge the verified commits into local `main` and
create annotated tag `v0.18.0` on that unified repository commit. The tag
identifies this accepted scope and the normalized source layout. No GitHub
push is authorized. Existing historical marker meanings are not reused or
changed.

## Final v0.18 release acceptance (2026-10-04)

The developer accepted the corrected single-precision Fortran results and
authorized merging `fix/fortran-single-precision-precip` into `main`, then
moving the existing annotated `v0.18.0` tag to that merge commit. The original
tagged commit, `2b62c291b3ab4e3da7a822559d341e3183bc302b`, remains in the
ancestry. Frozen reference data remain unchanged. This final release scope
extends the original acceptance above with the precipitation evaluation
correction and the tested mixed-precision configuration.

- Default-real32 prognostics, thermodynamic work arrays and tendencies are
  supported in the tested GNU configuration; PMB and input reads remain
  binary64. The existing makefile defaults continue to use real64.
- Native precipitation evaluation avoids real32 softplus overflow and replaces
  the finite-increment theta_e derivative with the derivative of the existing
  formula. The original precipitation law and masks are retained.
- Completed three-hour singleACE and twelve-hour multiACE checks demonstrate
  finite states, nonnegative total water and active precipitation. The matched
  corrected real64 multiACE control closely reproduces MATLAB.
- The developer accepts the common physical response: the initial outer
  ACE 8 disturbance propagates inward and excites ascending motion. Observed
  long-integration real32 trajectory differences are accepted for this
  milestone; numerical trajectory equality is not claimed.
- P3 integration is planned for v0.20 and is outside this release scope.
