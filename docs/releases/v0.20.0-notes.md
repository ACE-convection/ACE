# ACE v0.20.0

Released scope accepted by the developer on 2026-10-12 after reviewing the
three-hour evolution and precipitation figures. The developer accepts the
observed differences for this milestone and authorizes release and merge
into `main`. Further trajectory comparison and drift attribution are deferred.
This decision supersedes the earlier release-candidate recommendation and
pre-release acceptance language; it does not resolve the limitations below.

## Changes

- Promote the author-selected November 2025 KHN26 MATLAB dynamics and paired
  utilities, with a shared NetCDF input and 101-ACE slab configuration.
- Align the Fortran native MF/theta_e/qt path with the MATLAB dynamics,
  thermodynamic expressions and k=2 WENO calculation.
- Provide packed PMB response and optional OpenMP over independent outputs.
  Each output retains its inner summation order. P3 microphysics is serial.
- Include the historical Fortran P3 5.3.1 integration: MF, theta, qv, qc,
  nc, qr, nr, qi, ni, qrim, brim. MATLAB remains the native reference and
  does not implement P3.
- Preserve reproducible short gates, three-hour drivers, comparison figures,
  diagnostic source patches, configurations and result hashes.
- Add minute precipitation accumulation to isolated diagnostic runners:
  initial zeros, minute amounts and running totals in mm water equivalent.
  This is not a new default output of the production drivers.

## Accepted evidence

The tested KHN26 long cases use the shared Manaus profile 1342, dt=4 s,
a saturated +1 K ACE-1 bubble and 180 minutes of integration. They are
separate from the unmodified dt=6 s, +0.25 K, six-hour driver defaults.

- The WENO-aligned native multiACE MATLAB/Fortran runs completed with 181
  minute-spaced states, finite saved values and nonnegative total water.
- Fortran P3 singleACE and multiACE completed with 181 saved states, successful
  exits, finite fields, nonnegative water/number/riming fields and qrim <= qi.
- The final multiACE precipitation replays completed for MATLAB native,
  Fortran native and Fortran P3. All three have 181 precipitation records,
  and every saved-state stream exactly reproduces its own previous reference.
  This equality is within each implementation, not between the three models.
- MATLAB uses platform-default threads (80 computational threads on the test
  host); both Fortran replay builds use GNU real64 and assert 32 OpenMP threads.
- Focused minute-output bookkeeping and checked/production-prefix gates passed.
  Saved-state checks do not establish validity of every intermediate timestep.

## Known differences and limitations

1. **MATLAB/Fortran trajectories differ.** Operation order, reductions,
   bubble saturation, real versus complex thermal inversion and exceptional
   input handling differ. The native 1e-8 precipitation finite difference
   can amplify upstream roundoff. WENO alignment reduces some discrepancies
   but does not eliminate late drift or establish its unique first cause.
   The developer accepts the current results without additional attribution.
2. **Native and P3 are different physics.** Native precipitation is actual
   applied column-integrated water removal; P3 reports transported surface
   liquid/solid precipitation. Their timing and totals need not agree.
   P3 prognostics also differ from native theta_e/qt, and qrim is already
   included in qi when computing total water.
3. **SingleACE comparisons have a configuration mismatch.** The preserved
   earlier native singleACE run has initial MF amplitude 0.03; the P3 run
   starts with zero MF. Their paired MF plots cannot isolate a P3 effect.
   SingleACE masks dynamics tendencies outside ACE 1; physics, damping and
   the area-mean MF projection can still affect the other columns.
4. **P3 edge cases remain open.** Earlier isolated dry/warm wrapper probes
   encountered invalid floating-point operations. The completed coupled case
   does not demonstrate that those failures are fixed. Environmental cloud
   and ice are initialized from thermodynamic inversion while particle numbers
   and riming fields initially are zero; this initialization needs broader
   review. Checked P3 runs also report underflow/denormal flags.
5. **Validation is scoped.** KHN26 real32 numerical acceptance, complete
   six-hour production defaults, other compiler/platform combinations,
   other profiles and wider physical configurations are not certified by
   these three-hour GNU real64 tests. v0.18 real32 acceptance does not transfer
   automatically to the new KHN26 native/P3 paths. Full water/energy budget
   closure and independent observational validation remain unestablished.
6. **Output contracts differ.** MATLAB normal output uses double NetCDF;
   Fortran nine-field output uses real32 storage even for real64 integration,
   while comparison state streams use binary64. Native rain/riming slots are
   zero. P3 uses theta/qv in slots where native uses theta_e/qt. Existing native
   slots are not cumulative rainfall. Minute accumulation is provided by
   `tests/khn26/precip_timeseries.py`, which creates diagnostic source copies.
7. **Optional numerical paths are outside scope.** PMDv/PMD placeholders are
   disabled and rejected if enabled. Higher-order WENO and optional MATLAB
   diffusion/response truncation are not certified across implementations.
   Fortran sponge caching assumes fixed grid and dt within one process.
   MATLAB dry/disabled-physics sink evaluation and high-condensate overflow
   handling differ from Fortran; exceptional-input equivalence is not claimed.
8. **P3 data are external.** Supply `p3_lookupTable_1.dat-v6.4-2momI` through
   `--p3-lookup-directory`; the table is not bundled in this repository.
   Tested SHA-256: `57d2e839b4bbc52fa15892ac47d04a76c0854577a5df34dae264e55bdad4baf3`.
   P3 source declares version 5.3.1; lookup filenames have their own version
   convention. Upstream revision equivalence and third-party terms are not
   established by the coupled-runtime tests.

## Reproduction and provenance

Start with [MATLAB instructions](../../matlab/README.md),
[Fortran build instructions](../../fortran/README.md),
[KHN26 tests](../../tests/khn26/README.md) and
[shared input](../shared_input.md). Materialize the shared input through
Git LFS. Python postprocessing requires NumPy and Matplotlib; GNU Fortran
builds require netCDF-Fortran (`nf-config`). MATLAB requires the dependencies
of its driver, including Statistics and Machine Learning Toolbox for `normpdf`.
The replay input SHA-256 is
`09408f4d0343afd8659df82f8f1cfe5dc59308cff150fb2bcfd569b1b8794d35`.

On the original test host, prepare a fresh, nonexistent workspace:

```bash
python3 tests/khn26/precip_timeseries.py NEW_WORKSPACE --prepare --cases multiACE
python3 tests/khn26/precip_timeseries.py NEW_WORKSPACE --launch
```

The replay runner reads lookup and reference paths from preserved run
configurations; it has no command-line lookup override. On another host,
those reference workspaces and their paths must first be restored or adapted.
The runner checks preserved reference artifacts, which are not all bundled
in Git. Use the production Fortran `--p3-lookup-directory` option for
independent P3 runs. Full raw state streams remain in ignored runtime workspaces;
versioned reports, hashes, patches and plotting artifacts preserve the evidence.
The stopped six-job diagnostic workspace remains stopped and is not resumed
or rewritten by this release.
