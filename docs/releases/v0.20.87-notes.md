# ACE v0.20.87 — Fortran OOP preservation milestone

This release integrates the behavior-preserving Fortran OOP refactor into
the unified MATLAB/Fortran ACE repository. It retains the accepted v0.20.0
scientific baseline and preserves the original ACE_FORTRAN Git history.
The version identifies this unified repository milestone; it does not import
the separate historical MATLAB v0.24.87 snapshot.

## Changes since v0.20.0

- Introduce `ace_t` with ownership of initialization, prognostic/reference
  arrays, geometry, response tables and work arrays.
- Move integration time/options and thermal caches into the model, with
  type-bound `initialize`, `integrate`, `diagnose` and output methods.
- Give each model its own output unit, record counter, diagnostic buffers
  and first-use damping cache. Preserve existing CLI parsing, output cadence,
  array layouts, precision choices and numerical operation order.
- Move the P3 wrapper lookup option, first-use flag and iteration counter
  into the model. Enforce one P3 wrapper context per process because the
  unchanged third-party library retains process-wide state.
- Add staged regression and ownership/lifecycle contracts, reproducible
  result reports and final native/P3 three-hour preservation evidence.
- Link ACE_FORTRAN reference `b3f922e48e238581a85d31469bafcb800569a748`
  through history-only merge `af399d7`, preserving the 13 commits beyond
  previously integrated `88e4af5`. Original commit hashes, authors, messages
  and parent relationships remain. Reference source changes are retained
  as history rather than applied wholesale to ACE.

OOP and reference-history integration reached `main` in merge `8eb5446`.
The history-only merge and main integration both preserve the validated
OOP branch tree. MATLAB source, scientific formulas, production defaults,
tolerances and third-party P3 source were not changed by this refactor.

## Validation

All OOP-0 through OOP-5b gates passed. The final staged comparison retained
195 artifacts exactly against the frozen v0.20 baseline. Ownership contracts
check initialization, all nine RK observation frames, diagnostic isolation,
output bookkeeping, native damping and the P3 wrapper lifecycle. Dry/native
600-second gates retain 151 identical saved states. Serial/OpenMP real32 and
real64 compilation/link checks passed; these do not certify real32 runtime.

Final multiACE native and P3 preservation runs use the accepted shared Manaus
profile 1342, saturated +1 K ACE-1 bubble, zero initial MF, dt=4 s, 10,800 s
integration and GNU real64 with an actual 32-thread OpenMP team. Each ran in
a fresh process. These are distinct from the unchanged production defaults
of dt=6 s, a +0.25 K bubble and six hours.

| Artifact compared with its accepted Fortran reference | Native | P3 |
| --- | --- | --- |
| 181 saved states, including environment and initial reference Tv | Bitwise identical | Bitwise identical |
| 181 nine-field real32 normal output records | Bitwise identical | Bitwise identical |
| 181 minute/cumulative precipitation records | Bitwise identical | Bitwise identical |

The independent audit verified hashes, record layouts/counts, finite saved
states and outputs, nonnegative water/number fields, P3 rimed mass no greater
than ice mass, and precipitation bookkeeping. This equality compares each
Fortran implementation before and after OOP; it does not establish equality
between MATLAB, native physics and P3.

## Retained limitations

- The scientific differences and open issues documented in
  [v0.20.0 notes](https://github.com/ACE-convection/ACE/blob/v0.20.87/docs/releases/v0.20.0-notes.md)
  remain, including MATLAB/Fortran trajectory drift, differing native/P3
  precipitation definitions and earlier isolated P3 edge-case failures.
- Only one P3 wrapper context may be used per fresh process, across model
  and procedural APIs. A second context is rejected before a second library
  call. Concurrent P3 use, copying initialized P3 models, resetting models
  and independent mixed-configuration P3 instances are not certified.
- Sequential native instances with differing grid/dt are tested. Initialize
  each object once and keep its grid/dt fixed; concurrent integration and
  general reset/copy lifecycles are outside acceptance. Close output explicitly
  before reopening; copying a model with open output is unsupported.
- No new acceptance is claimed for singleACE long runs, real32 numerical
  runtime, other compilers/platforms, full six-hour defaults, performance,
  wider physical configurations or complete water/energy budget closure.
- The pre-existing damping `Ref` dummy layout and GNU executable-stack
  requirement for validation/saved-state callbacks remain documented.
- Minute precipitation accumulation remains a diagnostic-runner output.
  Production nine-field output and native rainfall-slot meanings are unchanged.

## Build and reproduction

Follow the
[Fortran instructions](https://github.com/ACE-convection/ACE/blob/v0.20.87/fortran/README.md),
[MATLAB instructions](https://github.com/ACE-convection/ACE/blob/v0.20.87/matlab/README.md)
and [shared-input instructions](https://github.com/ACE-convection/ACE/blob/v0.20.87/docs/shared_input.md).
Obtain the 101-ACE operator-containing input separately under the
[current local-only policy](../maintenance/large_basis_policy.md); Git LFS
retains only allowed small historical inputs. GNU Fortran builds require
netCDF-Fortran (`nf-config`); Python numerical postprocessing requires NumPy.

P3 requires the external `p3_lookupTable_1.dat-v6.4-2momI` via
`--p3-lookup-directory`; it is not bundled. The tested lookup SHA-256 is
`57d2e839b4bbc52fa15892ac47d04a76c0854577a5df34dae264e55bdad4baf3`.

On the original validation host, reproduce in a fresh workspace:

```bash
python3 tests/khn26/oop_long_regression.py NEW_WORKSPACE --prepare
python3 tests/khn26/oop_long_regression.py NEW_WORKSPACE --run
```

The paired preservation runner needs archived reference artifacts and lookup
paths from the original validation environment. Full raw state streams remain
in ignored workspaces; versioned reports and hashes preserve the evidence.
A fresh clone alone does not contain all long-run references.

The annotated `v0.20.87` tag identifies MATLAB and Fortran together. Previous
release tags and historical commits remain available.
