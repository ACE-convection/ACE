# ACE v0.21.87 — 88-ACE GOAmazon eight-hour milestone

This release changes the default case to the author-supplied
88 equal-width (5 km) ACE basis and GOAmazon filtered sounding profile 314.
The default is an eight-hour run, dt=6 s, dz=100 m and 40 km depth,
with the supplied PMDv/DHv and PMD/DHh momentum response terms enabled.
The developer accepted the observed eight-hour results and MF/gravity-wave
response plots on 2026-10-15 and authorized commit, merge into `main`, and
the `v0.21.87` tag. Acceptance applies to the tested native-precipitation case;
it does not extend the separate P3, precision or compiler claims below.

The current MATLAB and Fortran initialization policies are retained:
invert environmental theta_e/qt, reconstruct reference Tv, apply a saturated
+0.25 K bubble in ACE 1 at levels 11–51, and start with zero MF.
The current precipitation sequence is retained: dynamics/SSPRK and water
clipping, refreshed native precipitation, then damping. The author's changed
precipitation sequence and interpolated-temperature bubble were not adopted.
Thermodynamic helpers, WENO, constants and P3 source are unchanged.
Enabling PMD exposed a pre-existing Fortran unit-mapping defect: its SI
`ioflow^2/A` forcing was 1e6 times the MATLAB km^2 convention expected by
the supplied native PMD. The Fortran forcing is now divided by 1e6 before
contraction. This is a scientific bug fix, separately identified from the
case/default changes. A common nonzero-MF probe confirmed the scale at
coincident basis edges to about 5.6e-18 before correction; the combined
response must be interpolated after conversion because makima is nonlinear.
The original supplied main is preserved in
`docs/migration/v02187_author_sources.tar.gz` for traceability.

## Inputs and switches

- Original basis: `data/basis/COMPOSITE_ACE_BASIS_2D.mat`.
- Raw sounding: `data/soundings/maoarmbeatmM1.c1.20140101.003000.nc`.
- Shared case: `data/input/goamazon314_88aces.nc`; associated provenance
  records the exact input identities and conversion policy.
- MATLAB: `ACE_DHH=on|off`, `ACE_DHV=on|off`, `ACE_DT` and existing input,
  physics, smoke and output controls. Both momentum switches default on.
- Fortran driver: `--dhh on|off`, `--dhv on|off`, existing `--dt`, `--input`
  and `--intervals`; default shared slab duration is 480 minute intervals.
- The `ace_t%initialize` API appends optional `turn_off_DHv_input` and
  `turn_off_DHh_input`. Omitted arguments retain its previous disabled
  momentum behavior; the production CLI explicitly requests the new defaults.

Source operator coefficients are copied as binary64 without rescaling.
Both momentum variables retain the existing `native` units contract.
The vertical basis edges are identical to the older case, but geometry and
operator shapes differ; old/new basis equality is not claimed. NetCDF
operators use complete vertical chunks for one forcing/response pair to
avoid repeated decompression in the production reader.

## Momentum storage layout

PMDv and PMD now use the same source-contiguous layout as packed PMB.
Independent output points share the existing OpenMP work distribution;
vertical-then-forcing sum grouping and separate PMB + PMDv + PMD addition
order are retained. Packing is a permutation of unchanged binary64 values,
with one temporary operator at a time. The developer authorized this change
after the initial enabled-momentum short run showed high strided-access cost.
Bitwise preservation against the pre-layout component and integration
artifacts is required; new numerical tolerances are not used for this check.
The complete four-mode component outputs, native and four nonzero-MF single
steps, old-case ten steps and P3 single step retain identical saved bytes.
A controlled native single-step measurement (GNU real64, eight requested
threads, excluding initialization/compilation) improved from 70.15 s to 2.04 s;
this is a one-step measurement, not long-run performance acceptance.

See [test architecture](../../tests/slab/README.md) and the

all three operators have exact source readback; corrected four-mode momentum

The new production MATLAB/Fortran native one-step comparison passes existing

The packed physics-off and native ten-minute gates and their independent

ten-minute refinement screen passed with eight-thread settings; it was not
repeated as a complete 32-thread refinement suite. The final 32-thread

The eight-hour run completed 4,800 steps and 481 saved minute states. Fields
are finite, qt is nonnegative and water-inventory records are continuous.

## Execution and performance

Use 32 threads for both implementations. In MATLAB, run
`maxNumCompThreads(32)` before `ace`; for Fortran set `OMP_NUM_THREADS=32`
and `OMP_THREAD_LIMIT=32`. On the tested host the eight-hour MATLAB run took
about 6 h 45 min 48 s and Fortran 3 h 28 min 27 s, including initialization.
Other concurrent tests and hardware affect timing; this is not a performance
guarantee. Fortran's printed `cpu_time` is not elapsed wall time.

The pure-MATLAB Precomputed optimization remains a benchmark-only prototype.
It is not used by the production code, accepted trajectories or release
defaults. Its changed floating-point grouping and single-step performance
evidence are documented in
[the independent benchmark](../../benchmarks/nonlocal_response/PRECOMPUTED.md).
Integration of that prototype requires a separate decision and validation.

For the older Manaus input, explicitly disable both momentum switches.
The developer subsequently required all v0.21-and-later basis payloads to
remain local-only, including shared NetCDFs embedding response operators and
their byte parts. Obtain these separately and place them at the paths above;
they must not be added to Git or uploaded through LFS. Provenance, per-part/full
hashes and the materializer remain available for verification and reconstruction
from separately supplied local parts. Existing matching runtime files are
verified; differing files are never overwritten. At the developer's request,
the post-v0.20.87 release history is rebuilt without the new basis/operator
payload pointers; earlier historical inputs remain unchanged. Removing refs
does not itself guarantee deletion of already stored server objects or caches.
P3 still requires external lookup data.
